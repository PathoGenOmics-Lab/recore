Evolutionary events

evolutionary_events.tsv is an interpretation layer, not a new correction policy. Its job is to answer a different question from the corrected matrix:

  • The corrected matrix asks: is there enough evidence to mark this cluster as present in this genome?
  • The evolutionary audit asks: what biological or technical process best explains the cluster-level pattern after correction?

The two answers are deliberately kept separate. A cluster can remain a real matrix cluster while the recommended wording says "reference-gene derivative", "paralog/duplication signal", "fragmented homology", or "review before claiming novel acquisition".

Evidence used#

Each molecular_mechanism call combines:

  1. corrected cluster state after accepted rescues and optional NSC support;
  2. reference-genome audit and reference-derived cluster events;
  3. local locus-context stability and synteny/paralog rejection evidence;
  4. optional tree parsimony, including explicit ambiguous-root reporting;
  5. optional sequence-based mobile-element support;
  6. connected components of related clusters, so paralogous, redundant, split, or annotation-linked clusters are interpreted together.

Tree tips are matched to matrix columns by exact name or embedded ASxxxxx identifier. If only a subset of tips matches, evolutionary counts and patterns are calculated on the matched subset and the run summary/log warns about the incomplete match.

The tree is used for topology-based interpretation. Recore first scores the corrected presence/absence pattern on the matched tree using binary parsimony and a Dollo-like single-origin model. This produces fields such as phylogenetic_pattern, phylogenetic_blink_flag, carrier_mrca_purity, dollo_origin_purity, and penalized_phylo_score. Branch lengths are preserved for the HTML viewer, but the mechanism call itself is conservative and is driven primarily by evidence type, locus context, and topology.

Decision order#

The mechanism call is a deterministic evidence ladder. Direct molecular/locus evidence has priority over a visually attractive tree pattern, because a clean clade can still be caused by a reference allele, paralog collapse, gene fragmentation, or annotation boundaries.

  1. Reference-derived event check. If reference_cluster_events.tsv links the cluster to a gene in the audited reference, Recore first decides whether the cluster is a full-length/same-gene allele, a short/long in-frame allele, a frameshift/truncation/extension, or partial reference homology. If the same signal is also paralogous or multi-locus, it is treated as duplication_or_paralog_expansion.
  2. Mobile-element disruption check. If a disrupted or fragmented rescue has nearby mobile-element evidence within the conservative window, Recore calls IS_interruption_supported. With --mobile-element-reference, this is sequence-based and name-agnostic; without it, Recore falls back to annotation labels such as insertion sequence, transposase, integrase, phage, or recombinase terms.
  3. ORF integrity check. Pseudogene evidence is called pseudogenization; fragmented or split homology is called gene_fragmentation_or_structural_break.
  4. Paralog and locus-context check. Explicit paralog evidence, unstable locus context, or multi-locus behaviour becomes duplication_or_paralog_expansion.
  5. Synteny rejection check. Strong sequence similarity in an incompatible local context becomes translocation_or_context_shift_candidate, because it may represent a real sequence at the wrong locus, a translocation, or a paralog/annotation problem.
  6. Annotation/redundancy check. Split genes, start-boundary shifts, or NSC representative/member relationships become annotation_or_clustering_artifact.
  7. Reference-absent clade check. Only after the previous traps are ruled out, a cluster absent from the reference and concentrated in a lineage/clade can become clean_insertion_or_acquisition_candidate.
  8. Reference loss check. If the reference is absent but the inferred root state is present, Recore prefers reference_or_lineage_loss_candidate over "gain everywhere else".
  9. Tree loss/homoplasy/retention check. Ancestral or recurrent losses become deletion_loss_candidate; highly recurrent gain/loss patterns become unstable_or_homoplastic_accessory_signal; conserved ancestral presence becomes ancestral_retained_no_disruption.
  10. Fallback. If the available matrix, reference, synteny, mobile-element, and tree evidence do not resolve the process, Recore reports unresolved_accessory_variation.

How to use the calls#

Use phylogenetic_pattern to describe where the signal sits on the tree. Use molecular_mechanism to describe what process is the safest interpretation. Use recommended_wording for manuscript text, because it is written to avoid overclaiming.

For manuscript highlighting, the safest candidates are usually clusters with:

  • clean_insertion_or_acquisition_candidate, reference_or_lineage_loss_candidate, or deletion_loss_candidate;
  • coherent phylogenetic_pattern with low/moderate blink flag;
  • high carrier_mrca_purity or dollo_origin_purity;
  • no paralog/component warning;
  • compatible synteny and clear ORF integrity;
  • absent_not_searched of 0, so every absence the call rests on was searched (see below).

Clusters with duplication_or_paralog_expansion, annotation_or_clustering_artifact, translocation_or_context_shift_candidate, or unstable_or_homoplastic_accessory_signal can still be biologically interesting, but they should be presented as review/complex-locus signals until the locus is inspected manually. Clusters with reference_gene_* or partial_reference_homology should not be described as completely novel reference-absent genes, even if the original pangenome matrix marked them as absent from the reference.

Calls that rest on gaps Recore never searched#

Gains and losses are made of absences: a gain needs the gene missing in the rest of the tree, a loss needs it missing where it was lost. A gap outside the search (a cluster below --min-prevalence, a cluster with no sequence to search with, or a genome with no FASTA) keeps the input matrix's call, so a call built on such absences is only as good as that call. Under the default prevalence floor that is every gain on a cluster in fewer than one genome in ten.

absent_not_searched counts those absences and not_searched_reason says why (low_prevalence, no_cluster_sequence or no_fasta). For the calls that rest on absences (clean_insertion_or_acquisition_candidate, reference_or_lineage_loss_candidate, deletion_loss_candidate, unstable_or_homoplastic_accessory_signal and unresolved_accessory_variation):

  • when none of the absences behind the call were searched (for a reference loss, when the reference genome's was not), support_level drops one level, mechanism_detail gains absences_not_searched, and recommended_wording says so. The lower support lowers evolutionary_signal_score, and with it highlight_priority;
  • when only some were not searched, mechanism_detail gains absences_not_searched=N/M and the wording says how many, but the searched absences still carry the call.

Calls made from rescue evidence (pseudogenes, fragments, paralogs, reference events) do not rest on absences and are left as they are.

Where the fields live#

Every field named on this page is a column of evolutionary_events.tsv; its schema is in Output files. The report colours the matrix by molecular_mechanism when you ask it to, and its mechanism cards double as column filters: see Run report.
